# LMR33630A のシミュレーション（ngspice）

TI の暗号化されていない PSpice モデルを `tools/spice/pspice2ngspice.py` で書き換えて使う。

```sh
./get_model.sh                     # モデルを取得して変換（www.ti.com への接続が要る）
ngspice -b buck_12v_2a.cir         # 20V → 12V / 2A（6ms、約 30 分）
ngspice -b buck_0v8_startup.cir    # 20V → 0.8V の起動手順の確認（途中で止まる。下記）
```

## 必須の設定

- `.tran ... uic`：初期値計算を飛ばす。付けないと初期値計算が失敗して出力が 0.87V から始まり、1.926ms で「Timestep too small」で止まる。周波数も 250kHz と誤って見えていた
- `.save` で保存する波形を絞る：全部を保存すると 6ms 分でメモリが足りなくなり、強制終了される

## 結果（2026-11-09）

| ケース | 結果 |
|---|---|
| 20V → 12V / 2A（`buck_12v_2a.cir`） | ソフトスタート 4ms で立ち上がり、**12.005V、リップル 24mVp-p**。周波数 **386kHz**（仕様 400kHz）。インダクタ電流 0.93〜2.75A |
| 0.8V、起動時から FB 注入（Vctl 3.296V 固定） | **起動しない**。FB が最初から 0.95V あり、スイッチングが始まらないまま約 38µs でヒカップ（休止）に入り、ソフトスタートが毎回リセットされる。負荷 0.4Ω でも 6Ω でも同じ |
| 0.8V、起動中は Vctl = 1.0V（`buck_0v8_startup.cir`） | ソフトスタートの電圧が FB を追い越した 1.15ms からスイッチングを始めた（プリバイアス起動）。ただし負荷 0.4Ω をつないだまま出力が 12V に向かうので、1.4V で電流が 4A に達し、電流制限が働いたところで計算が止まった（1.53ms）。**試験の組み方の問題**で、回路の問題ではない |

## 設計への示唆

- **起動中は FB への注入を止めておき、ソフトスタートが終わってから（PG が立ってから）注入を始める**。注入の経路に MCU で切れるスイッチを入れる案が有力（VAR-06a の「CC ループを切り離せる」とも相性が良い）
- 0.8V / 2A の最小オン時間の確認は、軽い負荷で 0.8V にしてから負荷をつなぐ試験に組み直して、P2 で行う
