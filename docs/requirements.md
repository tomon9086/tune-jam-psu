## 1. 目的・概要

ブレッドボードに直接刺して使う**電圧可変の電源モジュール**を作る。
USB PD 充電器から給電し、ロータリーエンコーダで出力電圧と電流制限を設定する。
出力電圧と出力電流は OLED に常時表示する。

既存の MB102 系ブレッドボード電源（3.3V/5V 固定、保護なし）の代わりに使える、
**「小さな実験用電源」**として実験中の作業性と安全性を高めることが狙い。

### 1.1 スコープ
- 対象：回路設計、PCB 設計（JLCPCB 製造＋PCBA）、ファームウェア要件
- 対象外（Rev.A）：筐体、PC 連携（USB 通信による遠隔制御・ロギング）※将来拡張として 11 章に記載

## 2. 用語

| 用語 | 意味 |
|---|---|
| VAR | 可変出力チャンネル |
| CV / CC | 定電圧動作 / 定電流（電流制限）動作 |
| OCP / OVP / OTP / UVLO | 過電流保護 / 過電圧保護 / 過熱保護 / 低電圧ロックアウト |
| ソフトロック | 誤操作で設定値が変わらないよう、エンコーダ入力を無効化する機能 |
| レール | ブレッドボード両端の電源ライン（+/−） |

## 3. システム構成（ブロック図）

```
 USB-C (PD) ──┐
              ├─[入力保護: TVS / 逆接 / 突入制限]─ VIN(9〜20V)
 DCジャック ──┘  (Rev.Aはフットプリントのみ, OR接続)
                                   │
          ┌────────────────────────┼─────────────────────────┐
          │                        │                         │
   [補助降圧 5V]            [VAR 主電源: 降圧DC/DC]       [PDトリガIC]
          │                 0.8〜12V / 2A, CV/CC             │
     ┌────┴────┐                   │                     (MCUへ状態)
  [LDO 3.3V]  5V固定出力     [電流センス＋高速短絡検出]
     │                             │
  MCU / OLED / 3.3V固定出力   [出力スイッチ(ON/OFF)＋逆流防止]
                                   │
                         [レール選択ジャンパ] ── ブレッドボード 左右レール
                         VAR / 5V / 3.3V / OFF

  MCU ── I2C ── OLED, 電流電圧モニタ(, 電源IC)
      ── エンコーダ(A/B/SW), 出力ONボタン, NTC
```

## 4. 機能要件

### 4.1 入力電源

| ID | 要件 | 優先度 |
|---|---|---|
| IN-01 | USB Type-C レセプタクルから USB PD Sink として給電を受けること | 必須 |
| IN-02 | PD トリガで **20V を優先**して要求し、出せない充電器では 15V → 12V → 9V の順に下げること | 必須 |
| IN-03 | 交渉できた入力電圧に応じて、VAR の設定上限を自動で制限すること（目安：VIN − 2V 程度。詳細は設計時に決める） | 必須 |
| IN-04 | 5V しか出ない（PD 非対応の）電源をつないだ場合も、固定 3.3V 出力と表示は動くこと。VAR 出力は禁止するか、上限を制限すること | 推奨 |
| IN-05 | DC ジャック（5.5/2.1mm、THT）の**フットプリントだけ**用意し、Rev.A では実装しないこと。USB 入力とは逆流防止の上で OR 接続する | 必須 |
| IN-06 | DC ジャック入力の許容範囲：9〜20V | 必須 |
| IN-07 | 入力電圧と PD の交渉結果（要求した電圧・電流）を OLED に表示すること | 推奨 |
| IN-08 | PD 交渉が終わるまで DC/DC を止めておき、VBUS の容量制限と突入電流規定を守ること | 必須 |

### 4.2 可変出力（VAR）

| ID | 要件 | 優先度 |
|---|---|---|
| VAR-01 | 出力電圧範囲：**0.8〜12.0V** | 必須 |
| VAR-02 | 出力電流：**最大 2.0A**（連続） | 必須 |
| VAR-03 | 電圧の設定分解能：10mV | 必須 |
| VAR-04 | 電圧の設定精度：±(1% + 20mV) 以内（目標値。校正後の値） | 推奨 |
| VAR-05 | 電流制限の設定範囲：0.05〜2.00A、分解能 10mA | 必須 |
| VAR-06 | **CC（定電流）制限**：設定した電流を超えないよう、電圧を下げて電流を一定に保つこと。CV と CC は自動で切り替わること。**Rev.A から搭載する** | 必須 |
| VAR-06a | CC 制御ループは 0Ω 抵抗またははんだジャンパで切り離せること。切り離しても「電圧可変＋トリップ遮断」の電源として動くこと。CC 回路の部品は発注ごとに未実装（DNP）を選べること | 必須 |
| VAR-07 | **トリップ遮断**：設定した電流を超えたら出力を OFF にし、ユーザーが操作するまで復帰しないこと | 必須 |
| VAR-08 | CC 制限とトリップ遮断をユーザーが選べること | 推奨 |
| VAR-09 | 出力 ON/OFF を専用ボタンで切り替えられること | 必須 |
| VAR-10 | 電源投入時、出力は**必ず OFF** で起動すること | 必須 |
| VAR-11 | リップルノイズ：50mVp-p 以下（目標値、20MHz 帯域、1A 負荷） | 推奨 |
| VAR-12 | 出力を ON にしたとき、オーバーシュートは設定電圧の +5% 以内に抑えること | 推奨 |
| VAR-13 | 出力 OFF のときは出力を放電し、速やかに 0V 近くまで下げること | 推奨 |

> **CC 制限の実現方針（案）**：次のどちらかで検討する。
> - (A) CV/CC 制御を内蔵し、I2C から設定できる電源 IC を使う（部品点数が少なく実装が楽）
> - (B) 汎用の降圧 IC に、電流センスアンプとエラーアンプを外付けし、FB 端子に注入して CC を作る
>
> どちらにするかは、部品選定（8 章）で決める。現時点では (B) が本命。
> CC が成立しなかった場合も、VAR-06a により、トリップ遮断（VAR-07）とハードウェアの短絡保護（PRT-02）だけで使える電源として成立させる。

### 4.3 固定出力

| ID | 要件 | 優先度 |
|---|---|---|
| FIX-01 | 5.0V 固定出力：最大 1.0A（目標値） | 必須 |
| FIX-02 | 3.3V 固定出力：最大 0.5A（MCU と OLED の消費分は除く） | 必須 |
| FIX-03 | 固定出力も短絡で壊れないこと（電流制限付きの IC または eFuse/ポリスイッチ） | 必須 |
| FIX-04 | 固定出力は VAR 出力の ON/OFF とは独立させること（ジャンパで選んだ時点で常時出力） | 必須 |

### 4.4 ブレッドボード接続（形状）

| ID | 要件 | 優先度 |
|---|---|---|
| BB-01 | 標準ブレッドボード（830 穴／400 穴）の**端に直接刺せる**ピン配置にすること（MB102 互換の配置を基本にする） | 必須 |
| BB-02 | 左右のレールそれぞれについて、出力を **VAR / 5V / 3.3V / OFF** から選べること（ジャンパ等） | 必須 |
| BB-03 | GND は左右共通 | 必須 |
| BB-04 | レールへの給電ピンは MB102 と同程度の本数にすること。ブレッドボード接点の電流容量は利用者が管理するものとし、本機では対策しない | 必須 |
| BB-05 | ブレッドボードを使わずにリード線で取り出せる端子（VAR+ / GND、ピンヘッダ程度）。基板に余裕があれば付ける | 任意 |
| BB-06 | 基板の外形はブレッドボードの幅に収め、刺したときにブレッドボード本体の穴をできるだけ塞がないこと | 推奨 |
| BB-07 | OLED・エンコーダ・ボタンは上面から操作でき、USB-C は外側を向くこと | 必須 |

### 4.5 計測・表示

| ID | 要件 | 優先度 |
|---|---|---|
| MTR-01 | VAR の出力電圧・出力電流・電力を常時表示すること | 必須 |
| MTR-02 | 電圧の表示分解能 10mV、電流の表示分解能 1mA | 必須 |
| MTR-03 | 計測精度：電圧 ±(0.5% + 10mV)、電流 ±(1% + 5mA)（目標値。校正後の値） | 推奨 |
| MTR-04 | 表示の更新周期：5Hz 以上 | 必須 |
| MTR-05 | 表示器：**OLED（SSD1306/SH1106 系、128×64、I2C）** | 必須 |
| MTR-06 | 状態を表示すること：CV / CC / OUTPUT ON・OFF / LOCK / 保護動作（OCP・OVP・OTP など）/ 入力電圧 | 必須 |
| MTR-07 | 設定値（Vset / Iset）と実測値を見分けられる画面構成にすること | 必須 |
| MTR-08 | 消費電流量（mAh）や電力量（Wh）の積算表示 | 任意 |
| MTR-09 | 焼き付きを抑える対策（輝度調整、一定時間操作がないと減光） | 推奨 |

### 4.6 ユーザーインターフェース（操作）

**入力デバイス**
- ロータリーエンコーダ（押しボタン付き）×1
- 出力 ON/OFF ボタン ×1（タクトスイッチ）
- 状態 LED：出力 ON 表示（推奨）

| ID | 要件 | 優先度 |
|---|---|---|
| UI-01 | エンコーダを回すと、選択中の項目（Vset / Iset）が増減すること | 必須 |
| UI-02 | エンコーダを短く押すと、変更する桁（例：1V / 0.1V / 0.01V）を切り替えられること | 必須 |
| UI-03 | 編集対象を Vset と Iset で切り替えられること（操作の割り当ては FW 設計で決める。例：ダブルクリック） | 必須 |
| UI-04 | **ソフトロック**：エンコーダを**長押し（約 1 秒）**するとロックと解除が切り替わること | 必須 |
| UI-05 | ロック中はエンコーダの回転と短押しを無視し、画面にロックアイコンを出すこと。回されたときはロック中であることを短く知らせること（アイコンの点滅など） | 必須 |
| UI-06 | ロック中でも**出力 OFF の操作は常に受け付けること**（安全のため） | 必須 |
| UI-07 | ロック中に出力を ON にできるかどうかは設定で選べること（初期値は「許可」） | 任意 |
| UI-08 | ロック状態は電源を切っても保持すること | 推奨 |
| UI-09 | 将来、確認操作（例：ロック解除や大きな電圧変更の前に確認を挟む）を追加できるよう、FW を状態遷移で設計しておくこと | 推奨 |
| UI-10 | Vset / Iset / 保護モード / ロック状態を不揮発メモリに保存し、次回起動時に復元すること（出力は OFF のまま） | 推奨 |
| UI-11 | 出力 ON 中に Vset を変えたとき、すぐ反映するか確定してから反映するかを選べること（初期値はすぐ反映） | 任意 |
| UI-12 | 設定メニュー：保護モード（CC / トリップ）、ロック中の ON 許可、画面の輝度、校正 | 推奨 |
| UI-13 | エンコーダ入力のチャタリングをハードウェア（RC）とソフトウェアの両方で抑えること | 必須 |

## 5. 保護要件

| ID | 保護 | 要件 | 実現手段（案） | 優先度 |
|---|---|---|---|---|
| PRT-01 | 過電流（ソフト） | Iset を超えたら CC 制限またはトリップ（VAR-06〜08） | 電源 IC の機能、またはアナログ制御ループと MCU の監視 | 必須 |
| PRT-02 | 短絡（ハード） | 出力が短絡したら**ファームに頼らず**、目標 10µs 以内に出力を遮断すること。しきい値は固定（約 3A） | コンパレータで出力スイッチと DC/DC EN を切り、ラッチする | 必須 |
| PRT-03 | 出力過電圧 | Vset +10% または 13.5V を超えたら出力を遮断すること | MCU の監視（必須）、ハードウェアのクランプ（推奨） | 必須 |
| PRT-04 | 逆流 | 出力側に外部電源や大容量コンデンサがつながっても、入力（PD 充電器）側に電流が逆流しないこと | 出力の逆流防止（理想ダイオード/FET）。同期整流 IC は軽負荷時の逆方向動作を防ぐモードにする | 必須 |
| PRT-05 | 入力過電圧・サージ | VBUS / DC 入力のサージで壊れないこと | 入力 TVS。入力系の部品は耐圧 30V 以上 | 必須 |
| PRT-06 | 入力 UVLO | 入力が足りないときに不安定な出力を出さないこと | DC/DC の UVLO と MCU の監視 | 必須 |
| PRT-07 | 過熱 | DC/DC 周辺が規定温度（例：85℃）を超えたら出力を遮断すること | インダクタと IC の近くに NTC を置き、MCU が監視 | 推奨 |
| PRT-08 | ESD | 出力端子と USB 端子に ESD 保護を入れること | TVS / ESD ダイオード | 必須 |
| PRT-09 | 入力の逆接 | DC ジャックの極性が逆でも壊れないこと | 直列ダイオードまたは P-FET（ジャック用に OR 接続するダイオードで兼ねる） | 必須 |
| PRT-10 | 保護の通知 | 保護が働いたら、原因を OLED に表示すること。ユーザーが操作するまで出力を再開しないこと | FW | 必須 |
| PRT-11 | 固定出力の短絡 | FIX-03 と同じ | — | 必須 |
| PRT-12 | FW 暴走 | ウォッチドッグを使い、リセットしたときは出力 OFF で起動すること | IWDG と、デフォルト OFF のハードウェア構成 | 必須 |

> **PD 充電器の保護について**：一般的な PD 充電器には自前の OVP・OCP がある。それでも本機側で PRT-04（逆流）、PRT-05（サージ）、IN-08（突入電流）を満たし、充電器とケーブルにストレスをかけない設計にする。

## 6. 非機能要件

### 6.1 電気的特性・効率
| ID | 要件 |
|---|---|
| NF-01 | VAR の効率：12V/2A 出力（20V 入力）で 85% 以上（目標値） |
| NF-02 | 最大負荷を連続で流したとき、部品の温度上昇は周囲温度 +40℃ 以内（周囲 25℃、自然空冷） |
| NF-03 | 無負荷時の消費電流：出力 OFF で 30mA 以下（目標値、20V 入力時） |
| NF-04 | 動作温度範囲：0〜40℃（室内の机上で使う想定） |

### 6.2 製造（JLCPCB 前提）
| ID | 要件 |
|---|---|
| MFG-01 | 基板：FR-4、1.6mm 厚、**2 層を基本**とする（DC/DC のレイアウトが厳しければ 4 層も検討）。外層の銅箔は 1oz（2A 経路の電流容量を確認し、必要なら 2oz） |
| MFG-02 | JLCPCB の標準的な設計ルール（最小パターン幅・間隔、ビア径など）の範囲で設計し、追加料金のかかる仕様は避ける |
| MFG-03 | **SMD 部品はすべて JLC PCBA で実装する**（片面実装、Economic PCBA）。手元にホットプレートやホットエアがない前提のため |
| MFG-04 | **THT 部品はすべて手はんだにする**（ブレッドボード用ピン、エンコーダ、タクトスイッチ、ジャンパ用ピンヘッダ、OLED モジュール、DC ジャック） |
| MFG-04a | SMD 部品は **Basic Parts を最優先**し、次に Preferred Extended Parts（Economic PCBA なら部品ごとの追加料金がかからない）を選ぶ。通常の Extended Parts は**8 種類以下**を目標とする |
| MFG-04b | 機能が同じなら、受動部品は値の種類をそろえて BOM の種類数を減らす（例：プルアップや分圧抵抗の値を統一する） |
| MFG-05 | 部品はすべて LCSC の型番で BOM を作り、在庫が十分あるもの（目安：1,000 個以上）を選ぶ |
| MFG-06 | 部品の向きと位置を確認しやすいよう、シルクに極性と 1 番ピンの印を入れる |
| MFG-07 | 設計ツール：最終的な回路図・PCB データは **KiCad** で管理し、JLC 用の BOM/CPL は KiCad から出力する |
| MFG-08 | **回路図は Claude がコードベースのツールで書く**（AI が作成し、人がレビューする流れ）。候補：tscircuit、EasyEDA MCP、SKiDL など。KiCad に取り込めることを条件に P1 で評価して決める |
| MFG-09 | 回路図のソース（コードまたはテキスト）はこのリポジトリで管理し、差分でレビューできること |

### 6.2.1 コスト目標（Rev.A）

**基本方針**：開発費全体を最も下げるのは**試作回数を減らすこと**であり、部品代を削ることではない（試作 1 回で数千円と数週間かかる）。
検証パイプライン（6.5 節）で確かめやすいこと、事前の検証で確度を上げやすいことを、部品単価より優先する。

| ID | 要件 |
|---|---|
| CST-00 | 部品選定の優先順位：(1) 要件を満たすこと (2) 検証しやすいこと（SPICE モデルがある、データシートが明確、実績のある参考回路がある） (3) JLC の在庫が安定していること (4) Basic / Preferred であること (5) 単価。数十円の差なら、検証しやすい部品を選ぶ |
| CST-01 | PCBA は **2 枚**（JLC の最小数）、基板は 5 枚で発注する（残り 3 枚は予備の生基板） |
| CST-02 | 試作 1 回の総額（基板・PCBA・送料・関税・手はんだ部品・OLED）は **9,000 円以下**を目標とする（PD＋CC 構成） |
| CST-04 | 試作は**合計 3 回以内（Rev.A〜C）**で完成させることを目標とする |
| CST-03 | BOM の作成時に、Basic / Preferred / Extended の内訳と追加料金の見込みを一覧にする |

### 6.5 検証パイプライン（設計のフィードバックループ）

実機評価（1 回あたり数週間と数千円以上）を最後の判定とし、その前に**機械的に回せる安い検証**で、できるだけ多くのミスを潰す。
AI（Claude）が設計し、各検証の結果を見て直すループを回せるよう、**すべて CLI から実行でき、結果を機械的に判定できる**こと。

| ID | 層 | 要件 | 想定ツール | 実行タイミング |
|---|---|---|---|---|
| VER-01 | ERC | 回路図の電気的ルールチェック（未接続ピン、出力どうしの衝突、電源ピンの未駆動など）でエラー 0 件であること | `kicad-cli sch erc` | 回路図を変更するたび |
| VER-02 | DRC | PCB のデザインルールチェック（JLC の製造ルールを設定）でエラー 0 件であること | `kicad-cli pcb drc` | PCB を変更するたび |
| VER-03 | ネットリスト独自ルール | 次をスクリプトで検査すること：(a) 各 IC の電源ピン近くのパスコン (b) ネットの最大電圧 ≤ 接続される部品の耐圧（ディレーティング込み） (c) EN、BOOT、RESET などの制御ピンが浮いていない (d) I2C のプルアップ (e) 極性部品の向き | Python（ネットリストを解析） | 回路図を変更するたび |
| VER-04 | ピン対応の照合 | 主要 IC について、データシートのピン表と、シンボル・フットプリントのピン番号・機能の対応が一致すること（AI の読み違い対策） | Python ＋ データシートから作ったピン表（YAML/CSV） | 部品を追加・変更したとき |
| VER-05 | BOM / 部品チェック | 全 SMD 部品に LCSC 番号があり、在庫が十分あること。Basic / Preferred / Extended の内訳を出し、Extended Parts の種類数が MFG-04a を満たすこと | Python ＋ JLC/LCSC の部品データ | BOM を変更するたび、発注前 |
| VER-06 | 設計計算 | 分圧比と出力電圧の範囲、インダクタのピーク電流と飽和電流、損失と温度上昇、保護のしきい値、シャント抵抗の損失を計算し、要件の値（4〜6 章）と突き合わせて合否を出すこと | Python（設計計算書をコード化） | 定数を変更するたび |
| VER-07 | 回路シミュレーション | 次をシミュレーションで確認すること：(a) CC/CV 制御ループの安定性（位相余裕 45° 以上を目標） (b) 短絡遮断の応答時間（PRT-02） (c) 出力を ON にしたときのオーバーシュート（VAR-12） (d) 入力の突入電流（IN-08）。IC の SPICE モデルがない場合は、平均化モデルや理想化モデルで代用してよい | ngspice（CLI） | 関係する回路を変更したとき |
| VER-08 | ファームのホスト上テスト | UI の状態遷移（ロック、桁送り、保護状態からの復帰など）と、保護判定のロジックを PC 上でユニットテストできる構成にすること | ホスト向けビルド＋テストフレームワーク | FW を変更するたび |
| VER-09 | 実機評価の自動化（任意） | 計測器を PC から操作できる場合、効率、リップル、保護の応答、温度などの評価をスクリプトで実行し、結果を記録できること | SCPI / pyvisa など | 実機評価時 |
| VER-10 | まとめて実行 | VER-01〜08 を 1 コマンドでまとめて実行し、合否の一覧を出せること（CI 化も検討） | Makefile や justfile など | 随時 |

> **ツール選定への影響**：回路図ツール（Q7）は、この検証パイプラインに組み込めるかで評価する。最低条件は「ネットリストをスクリプトで読めること」と「KiCad 形式に変換して `kicad-cli` で ERC/DRC を回せること」。ngspice にネットや部品を流用しやすいことも加点する。

## 7. 安全上の注意（取扱説明に記載する項目）
- ブレッドボード接点の電流容量（製品によっては 1A 程度）は利用者の責任で管理すること
- 誘導性負荷（モーターなど）をつなぐときは、負荷側にフライホイールダイオードを入れること
- 出力に外部電源をつながないこと（逆流防止は入れるが、想定外の使い方）

## 10. 受け入れ基準（Rev.A）
1. 20V の PD 充電器をつなぐと PD 交渉に成功し、OLED に入力電圧が表示される
2. VAR を 0.8V〜12.0V の範囲で設定でき、2A の負荷で 30 分連続出力しても保護が誤動作しない
3. 電流制限（CC またはトリップ）が設定どおりに動く
4. 出力を短絡するとハードウェアで遮断され、本体も充電器も壊れない
5. 5V と 3.3V の固定出力をジャンパで左右のレールに割り当てられる
6. ロック中はエンコーダを回しても設定値が変わらず、出力 OFF の操作はできる
7. 電源投入直後は出力が OFF になっている
