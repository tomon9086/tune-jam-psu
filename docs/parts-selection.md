## 2. VAR 降圧 IC（最優先）

### 2.1 必須条件から導いた選定の基準

- **入力耐圧**：PD は 20V（最大 21V）。サージのときは TVS のクランプ電圧（SMAJ22A で 35.5V）までかかる → **絶対最大 36V 以上が欲しい**（要件は 28V 以上）
- **最小オン時間**：20V → 0.8V では、デューティ比が 4%。400kHz ならオン時間 100ns が必要 → **最小オン時間は 80ns 以下（最大値で）が必要**
- **CC で出力 0V 付近まで下げるとき**：FB 注入方式の CC で短絡に近い負荷になると、オン時間がさらに短くなる。最小オン時間で止まったときに周波数を下げる（または電流制限で止まる）IC でないと、電流が暴走する
- **FB 注入**：FB の基準電圧より低い出力も、注入電流で作れる（式は 2.3 節）。基準電圧 ≤ 0.8V は必須ではない
- **軽負荷**：PFM / パルススキップで、インダクタの逆電流を流さないこと（PRT-04 の補助）

LMR33630 の補足：
- 絶対最大の VIN 38V、PG 端子 22V（⚠️ データシートの抜粋）
- 電流制限：ハイサイド 4.5A typ、ピーク電流 0.72〜4.5A（✅ SPICE モデルのパラメータ `iminpk=0.72`、`imaxpk=4.5`）。FB < 0.4V でヒカップに入る ⚠️
- 最小オン時間で止まると周波数を下げ、オン時間は一定のまま（⚠️ データシートの記述）。モデルにも `fsmin_ratio=0.1`（最低 40kHz まで下げる）がある ✅
- FB 注入方式の CC では、ループが FB を 1.0V に保つので、通常はヒカップに入らない。CC ループが追いつく前にハードウェアの電流制限が働くと、FB が下がってヒカップに入ることがある（保護として許容する）
- **在庫**：JLC 28,841 個（2026-11-06）。以前のスニペットの 1,272 個から増えており、在庫の懸念はなくなった

### 2.3 VAR の定数の目安（P2 で計算スクリプトにする）

- FB 注入の式（オペアンプの出力 Vctl が Rinj を通して FB に入る場合）：
  `Vout = Vref·(1 + R1/R2) + (Vref − Vctl)·R1/Rinj`
  Vctl = 0V で最大電圧（約 13V）、Vctl を上げるほど出力が下がる。Vctl はおよそ 0〜3.3V。DAC 12bit なら約 3.2mV/LSB で、VAR-03（10mV）を満たす
- インダクタ：L = 10µH、400kHz で、リップル電流が最大になるのは Vout = 10V（VIN 20V）の 約 1.25Ap-p。12V/2A のときピーク 約 2.6A。**飽和電流は電流制限の 4.5A 以上**が必要 → SRP7028A-100M（Isat 6A、DCR 75mΩ）。DCR の損失は 2A で 0.3W
  - 代替：SWPA8040S100MT（C37429、8×8mm、29mΩ、$0.14）は飽和電流が 4.1A と電流制限より小さいので次点
- 効率：12V/2A・20V 入力で 90% 前後の見込み（4 章のシミュレーションで確認する）→ NF-01 の 85% は満たせる見込み

CH224A を推す理由：
- レジスタ 0x50 で「今の PDO で使える最大電流」（50mA 単位）が読める ⚠️。入力電力の上限（後述）を FW で守るのに使える
- レジスタ 0x60〜0x8F で Source Capabilities 全体を読める ⚠️ → IN-02 の「20V → 15V → 12V → 9V の順に下げる」を FW で確実に行え、IN-07（交渉結果の表示）も満たせる
- レジスタ 0x0A で要求電圧を切り替えられる ⚠️
- 注意：I2C は「抵抗 1 本での設定」のときだけ有効 ⚠️。USB-A 出力の充電器では電流のレジスタが無効 ⚠️
- CH224A と CH224Q は同じデータシート（CH224DS1）。P2 でデータシートの原本を確認する

**入力電力の予算（提案）**：全出力を最大にすると VAR 24W ＋ 5V 5W ＋ 3.3V 約 1W ＋ 内部 約 0.5W ≈ 30W、効率 90% で入力 約 34W。20V/3A（60W）の充電器なら足りるが、30W 以下の充電器では足りない。**PDO の電流から、VAR の電流上限を FW で自動的に下げる**ことを IN-03 に追加することを提案する

### 3.3 短絡検出・OVP（PRT-02/03）

- **LM393DR2G（C7955、Basic ✅）**：応答時間 1.3µs、伝搬遅延 300ns（✅ JLC の属性）。電源 2〜36V
- 1 回路目：INA180 の出力 > 3A 相当 → VAR 降圧の EN と出力スイッチのゲートを引き下げる。ラッチは正帰還か、MCU の GPIO でリセットする方式を P2 で決める
- 2 回路目：出力の過電圧（13.5V 相当）のハードウェアクランプ（PRT-03 の推奨部分）
- 同相入力の上限は VCC − 1.5V なので、LM393 は 5V 電源にし、入力は 3.5V 以下に収める

### 3.4 補助電源（Q5：決定済み、D13）

固定 5V / 3.3V 出力は「ついでに出せるなら出す」もの（ユーザーの判断）。**降圧は内部用の 5V 1 つだけ**にする。

- **5V**：LMR33630ADDAR（VAR と同じ型番）。内部の 5V（INA180、MCP6002、LM393、OLED）と固定 5V 出力（SY6280 で 1A 程度に制限）をまかなう。IC は 3A まで流せるので余裕がある
- **3.3V**：AMS1117-3.3（C6186、Basic）を 5V から作る。**内部用と固定出力用で 2 個に分ける**
  - 内部用：MCU、INA226、OLED など 約 50mA ❓ → 損失 約 0.09W
  - 固定出力用：0.2A で損失 (5 − 3.3) × 0.2 ≈ **0.34W**。SOT-223 で銅箔を広めにとれば（θja 約 60℃/W ❓）+20℃ 程度
  - 固定出力が短絡したときは、AMS1117 の電流制限と過熱保護で止まる（FIX-03 の「壊れない」を満たす）。MCU の 3.3V は別の LDO なので落ちない
  - 以前の案（SY6280 で 3.3V も制限）は、SY6280 の電流制限の下限が 0.4A で、0.2A に絞れないのでやめた
- 降圧は VAR と 5V の 2 つになり、面積の懸念はかなり減る

### 3.6 出力スイッチ・逆流防止（**要件定義書の候補を変える必要がある**）

**問題**：8 章の候補「P-FET（AO3401 系）× 2」は、ゲートを GND に引いても Vgs = −Vout にしかならない。Vout = 0.8V では、しきい値（−0.5〜−1.3V）を超えられず ON にならない。VAR-01 の下限 0.8V を満たせない。

GND は左右のレールで共通（BB-03）なので、ローサイドのスイッチも使えない。

**提案**：N-FET（AO3400A、C20917、Basic、30V、Vgs ±12V）× 2 をソース共通のバックツーバックにして、ハイサイドに置く。ゲートは VIN より高い電圧で駆動する。

- **ゲート電源**：MCU の PWM（3.3V、100kHz）を、ダイオード 2 個（BAV99、Basic）とコンデンサ 2 個のチャージポンプで **VIN の上に積む**（CP ≒ VIN + 3.3V − 2Vf ≒ VIN + 2.3V）
  - 以前の案（5V 降圧のスイッチノードを使う）は、LMR33630 が軽負荷で PFM（間欠動作）になるとポンプが止まるのでやめた
  - **FW が止まると PWM も止まり、ゲートの電圧が抜けてスイッチが OFF になる**ので、安全側に倒れる（VAR-10、PRT-12 と相性が良い）
- ゲート抵抗 100k、Vgs は 10V のツェナー（MMSZ5240B、Preferred）でクランプ
- OFF：LM393（短絡）または MCU がゲートを GND に引く。ツェナーが順方向に流れるので、Vgs が大きくマイナスになることはない
- Vout ≤ VIN − 2V（IN-03）なので、最悪でも Vgs ≒ 4.5V が確保できる

**シミュレーション結果**（2026-11-06、ngspice。`sim/output-switch/`。降圧の出力は理想電圧源、負荷 2A。AO3400A・BAV99・ツェナーは**データシートの代表値に合わせた手作りの近似モデル**）

| VIN | Vout | Vgs（ON） | スイッチの電圧降下（2A） | 2 個分の抵抗 | ON にかかる時間 | OFF 指令 → 電流 0.2A 以下 |
|---|---|---|---|---|---|---|
| 20V | 0.8V | 9.9V | 71mV | 35mΩ | 94µs | **0.53µs** |
| 20V | 5V | 9.9V | 77mV | 39mΩ | 13µs | — |
| 20V | 12V | 9.8V | 78mV | 39mΩ | 14µs | **0.53µs** |
| 15V | 12V | 5.6V | 99mV | 50mΩ | 21µs | — |
| 12V | 10V | 4.6V | 111mV | 56mΩ | 27µs | **0.52µs** |
| 9V | 7V | 4.6V | 111mV | 55mΩ | 34µs | — |

- **0.8V 出力でも ON になる**（P-FET 案の問題は解消）
- 損失は最大 0.22W（2 個の合計）。1 個あたり 0.11W で、SOT-23 でも余裕がある
- OFF 後の Vgs の最小値は −0.32V で、±12V の定格に対して問題ない
- **逆流**：スイッチ OFF、降圧 5V、出力に外部から 15V をかけたとき、降圧側に流れる電流は **3nA**（`reverse_block.cir`）→ PRT-04 を満たす
- 短絡時の遮断：PRT-02 の 10µs のうち、スイッチ自体は約 0.5µs。残りの時間を INA180（150kHz）と LM393（1.3µs）で使える
- 注意：0.8V 出力のときに 2A で 71mV 下がるので、VAR-04（±(1% + 20mV)）を満たすには、**スイッチの後ろで電圧を測って補正する**必要がある（INA226 のバス電圧をスイッチの後ろにつなぐ）
- 残りの確認：実際の AO3400A のモデル（Alpha & Omega 提供）での再確認、起動時に出力へ出るパルスの有無、PWM の周波数とコンデンサの値の最適化。P2 で行う

## 4. 検証しやすさ（SPICE モデル）

### 4.1 LMR33630 のモデルは ngspice で動く

TI の製品ページ（https://www.ti.com/product/LMR33630）に、**暗号化されていない PSpice 過渡解析モデル**がある。

- LMR33630A 用：`SNVMBF9A.ZIP`（.lib のみ）、`SNVMBF6A.ZIP`（PSpice のプロジェクト付き）。どちらも中の `LMR33630A_TRANS.lib` は同じもの
- サブサーキット：`LMR33630A_TRANS AGND BOOT EN FB PG PGND SW VCC VIN`
- ngspice-42 で動かすには、次の 3 つの機械的な書き換えが要る（P1.5 で変換スクリプトにする）
  1. `.PARAM` の中で、後で定義される値を先に参照している → 依存関係の順に並べ替える
  2. `{{a-b}/{c-d}}` のような入れ子の波括弧 → 内側を丸括弧にする
  3. 行の折り返しで数値が `0 .5` のように切れている → `0.5` に直す
- あわせて `.spiceinit` に `set ngbehavior=psa` を入れる（PSpice 互換モード）
- 20V → 12V / 2A の過渡解析：結果は 4.2 節

### 4.2 シミュレーションの結果

2026-11-06、ngspice-42 で実行（変換は `tools/spice/pspice2ngspice.py`）。1 本あたり 2ms 分の計算に約 5 分かかる。

| ケース | 結果 | 判定 |
|---|---|---|
| 20V → 12V / 2A（R1 100k、R2 9.09k、10µH、44µF） | 1.5ms で 12.0V に立ち上がる。1.80〜1.92ms の平均 **11.999V、リップル 26mVp-p**、インダクタ電流 0.95〜3.04A | ○ 動作する |
| 同上の周波数 | インダクタ電流のピークの間隔から **約 250kHz**（仕様は 400kHz） | ⚠️ 変換の誤りか、モデル本来の動作か未確認 |
| 計算の継続 | **1.926ms で「Timestep too small」で止まる**（発振器のノード `V_U3_V53`）。`method=gear` にすると 7µs で止まり、かえって悪い | ✗ 長い時間の解析ができない |
| 20V → 0.8V / 2A（FB 注入：Vctl 3.296V、Rinj 20.5k） | 1.4〜1.9ms の間、**一度もスイッチングしない**（出力 0V） | ✗ 未確認 |

0.8V のケースについての考察：
- 出力が 0V でも、注入電流で FB が約 0.95V に持ち上がる。ソフトスタートの基準電圧（`C_U2_C1` 4nF を 1µA で充電、約 4ms で 1V）が 0.95V を超えるまで、IC は「出力が高すぎる」と判断して待つ
- 1.926ms で計算が止まる問題があるので、その先が見えていない
- **実機の設計への示唆**：起動時は Vctl を 0V（＝最大電圧の側）にせず、**ソフトスタートが終わる（PG が立つ）まで注入を止めておき、その後に Vctl を上げる**シーケンスにする必要がありそう。出力スイッチは OFF のままなので、出力端子には出ない。FW の起動手順（VAR-10、VAR-12）として P2 で決める

結論：
- **モデルは ngspice で動き、12V の定常動作は確認できた**。「SPICE モデルがある」という加点はそのまま有効
- ただし、周波数のずれと 1.9ms で止まる問題があるので、VER-07 で使うには P1.5 で手直しが要る。候補：(1) モデル内の理想スイッチ（VSWITCH、Ron 1mΩ / Roff 1GΩ）を緩める (2) `.tran` に `uic` を付けて初期値計算を飛ばす（今回は初期値計算が失敗しており、t = 0 の出力が 0.87V になっていた） (3) 定常状態だけを見たいケースは、自作の平均化モデルで代用する
- 20V → 0.8V の最小オン時間の確認は、上の手直しをしてからやり直す

### 5.1 Extended を一切使わずに作れるか（2026-11-06 に調べた）

**作れない。** JLC の Basic / Preferred の一覧（約 1,600 件）に、次の部品が 1 つもない。

| 機能 | Basic / Preferred にあるもの | 結論 |

| パワーインダクタ（1A 以上） | なし（小さな信号用だけ） | Extended が必須 |
| VAR 降圧 IC | TPS5430（Basic、非同期、500kHz）、TPS54331（Pref）、XL1509（Basic、2A、150kHz）など | 20V → 0.8V の最小オン時間（80〜100ns）を満たすものがない → Extended が必須 |

| 電流電圧モニタ | なし | MCU の ADC で代用はできる（精度は下がる） |
| MCU | STM32F103C8T6 / STM32F030C8T6（Pref。DAC なし） | DAC なしで PWM ＋ RC フィルタにすれば使える |
| シャント | 100mΩ 1206（Basic）のみ | 4 本並列（25mΩ）にすれば使えるが、精度と温度係数が悪い |
| 固定 5V の保護（負荷スイッチ） | なし | 省くと、5V の短絡で内部の 5V も落ちて MCU が再起動する（壊れはしない） |
| NTC | なし | 省くことはできる |

**最少で 4 種類**（USB-C、PD の IC、インダクタ、降圧 IC）。これに INA180 を加えた 5 種類が、性能を大きく落とさずに作れる下限になる。

| 案 | Extended | 追加料金の目安 | 失うもの |
|---|---|---|---|
| 現案 | 10 種類 | 約 1,500〜4,500 円 | — |
| 中間案（NTC、INA226、SY6280 を外す） | 7 種類 | 約 1,000〜3,200 円 | 温度の監視、表示の精度（MTR-03）、5V 短絡時に再起動する |

- 追加料金は 1 種類 $1.5〜3 として計算（JLC の見積もり画面で要確認）
- 現案と最少案の差は 1 回あたり約 750〜2,200 円。D9（試作回数の削減を優先）に照らすと、**現案か中間案から NTC だけを外す案**が妥当と考える
